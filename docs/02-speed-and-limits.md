# 2. Швидкість і ліміти

Виміряно 2026-10-13 на живій сесії: Qwen3-Coder-30B (Q4_K_M), 2× Tesla T4, контекст 65536, прямі запити до `/api/chat`.

| Вимір | Результат |
|---|---|
| Пам'ять GPU | 26,3 ГБ, усе у відеопам'яті (вага ~18 ГБ + кеш контексту) |
| Генерація, короткий запит | 150 токенів за 2,7 с, ≈ 55 ток/с |
| Обробка запиту, холодна | 17 700–18 600 токенів за 19–21 с, ≈ 900 ток/с |
| Той самий запит вдруге | 0,6 с (кеш префікса) |

Висновки:

- Домінує генерація: файл на 2000 токенів ≈ 36 с. Для `ask_qwen` став `max_tokens` не більшим, ніж потрібно.
- Довгий контекст платиться один раз, повторні запити з тим самим початком майже миттєві.
- Старт ядра: черга + завантаження моделі (≈ 45 с на 18 ГБ) + прогрів. У автора від `push` до готовності було 5–9 хв.
  Час старту йде в квоту GPU.

Ліміти Kaggle: ≈ 30 год GPU на тиждень, сесія до ~9 год (`max_hours = 8` у `serve.py`), автовимкнення за 10 хв простою.
Квота рахується за час роботи ядра, а не за кількість токенів.

Контекст за замовчуванням у `serve.py` — 32768. 65536 теж влазить на 2× T4 (виміряно), але жере більше пам'яті.
Швидкість на інших GPU не вимірювалась.
